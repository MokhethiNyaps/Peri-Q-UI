# RastasperiQ website — Ordering + Yoco

Next.js **server** site for `rastasperiq.co.za` on Vercel (`website/` root). Shares the same Supabase Postgres as the Android app. Website and app both call `prepare_card_checkout` to create a private draft. Only the signed payment webhook calls `finalize_card_checkout`, which creates the authoritative paid order and its items atomically.

## Pages

- `/` — landing (hero with **Order on website** CTA, TodaysSpecialLive)
- `/menu/` — browse live `menu_items` + `menu_categories` (RLS public read), add to cart, server price re-validated at checkout
- `/cart/` — quantities ±, remove, subtotal, delivery fee preview
- `/checkout/` — name/phone, pickup/delivery + address, card-only payment, creates a draft via `prepare_card_checkout`
- `/order/[id]/` — order confirmation, fulfilment vs payment status separate, Yoco retry
- `/get-app/` — sends Android visitors into the Play Store app and shows a scannable QR to everyone else
- `/privacy-policy/` — public privacy policy for the Android app
- `/terms-and-conditions/` — customer ordering terms
- `/delete-account/` — public account-deletion instructions for users and Google Play
- `/api/yoco/checkout` — server creates Yoco hosted checkout (amount = trusted server total, `Idempotency-Key: client_request_id`)
- `/api/yoco/webhook` — server verifies Yoco Standard Webhooks signature (`whsec_...`), amount match, idempotent handling

## Get the app page

`/get-app/` is the short link printed on QR codes and marketing material.

- On Android it immediately navigates to `market://details?id=za.co.rastasperiq.ordering`, which the Play Store app handles, so the listing opens in the app rather than in a browser.
- If the navigation is blocked — in-app browsers such as Instagram, WhatsApp, and Facebook often drop custom schemes — a tappable "Open in Play Store" button appears after two seconds.
- Everywhere else it shows a QR code to scan with an Android phone, plus a link to the Play listing.

The rules live in `app/get-app/page.tsx` and `components/get-app-panel.tsx`; the
links are configured in `lib/site.ts` under `app`.

The page is prerendered in the server-mode Next.js build, so device detection happens in the browser after
hydration, not on the server. That is why the page renders a neutral "Checking
your device…" state first.

### QR artwork

The QR images are generated by `../marketing/qr/generate_play_store_qr.py` and
copied into `public/qr/`. After regenerating them, run:

```bash
pnpm sync-qr
```

which copies the two files the site uses: the branded square shown on the page
and the SVG offered as a print download.

## Run locally

Install [Node.js](https://nodejs.org/) and pnpm, then run:

```bash
pnpm install
pnpm dev
```

Open `http://localhost:3000`.

The verified WhatsApp contact is already enabled. To show Instagram, Facebook, or TikTok:

1. Copy `.env.example` to `.env.local` for local development.
2. Add the complete public profile URL after the matching variable.

## Shared ordering (single authoritative backend)

- Uses **same Supabase project** as the Android app (`NEXT_PUBLIC_SUPABASE_URL/_PUBLISHABLE_KEY`). Menu, `app_settings`, `orders`, `order_items`, `payments` and `yoco_webhook_events` are single source; no duplicate customer or menu tables.
- Website signs in anonymously (Supabase Auth → Anonymous enabled) like the app, then calls `prepare_card_checkout` RPC which server-calculates trusted totals and enforces store hours, availability, delivery fee.
- Never trust client total — Yoco amount is `checkout_intents.total_price * 100` verified server-side before creating checkout; webhook re-validates amount matches order before marking `paid`.
- `payment_status` (`unpaid/pending/paid/failed/...`) is separate from fulfilment `status` (`pending/preparing/ready/...`). The webhook finalizes the draft as a paid order, never auto-completes preparation.

## Connect Supabase + Yoco (Vercel env)

In **Vercel → Project Settings → Environment Variables** (Production + Preview as needed), add values only (no `NAME=` prefix, no quotes):

- `NEXT_PUBLIC_SUPABASE_URL` → `https://<ref>.supabase.co`
- `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` → `sb_publishable_...` (or anon JWT)
- `NEXT_PUBLIC_SITE_URL` → `https://rastasperiq.co.za` (used for Yoco redirects)
- `SUPABASE_URL` + `SUPABASE_SERVICE_ROLE_KEY` → same URL + **service_role** secret (server only, never `NEXT_PUBLIC_`)
- `YOCO_SECRET_KEY` → `sk_test_...` for testing, later `sk_live_...` for live (after domain verified)
- `YOCO_WEBHOOK_SECRET` → `whsec_...` matching the same Test/Live tab

`NEXT_PUBLIC_*` changes require a **Redeploy** (Next.js embeds them at build). Keep only `supabase publishable` in `NEXT_PUBLIC_*`; secrets live only in server env.

Yoco webhook URL to register (dashboard or API): `https://rastasperiq.co.za/api/yoco/webhook` — select events `payment.succeeded` + `payment.failed`. Use `https`; live requires domain verified in **Yoco App → Sales → Payment Gateway → Verified Domains**.

## Deploy to Vercel

1. Push the repository to GitHub, GitLab, or Bitbucket.
2. In Vercel, choose **Add New → Project** and import the repository.
3. Set the **Root Directory** to `website`.
4. Keep the detected framework as **Next.js** and deploy (server mode — no `output:"export"`).
5. In the Vercel project, open **Settings → Domains** and add `rastasperiq.co.za`.
6. Add the DNS records Vercel displays at the company where the domain is registered.
7. Add `www.rastasperiq.co.za` too and redirect it to the primary domain if desired.

Build is `pnpm build` → `.next/` (serverless functions `ƒ /api/yoco/*` visible in logs). There is no `out/` folder anymore. Check `https://rastasperiq.co.za/api/yoco/webhook` GET returns `{ ok:true }` after deploy.

## Website customer accounts

Customers can use `/account/` to sign up, sign in, edit their name and phone number, and view their orders. These accounts and profile fields are shared with the mobile app. Guest orders remain linked to their original guest identity; signing in does not reassign them.

Email confirmation and password recovery need these production URLs in Supabase → Authentication → URL Configuration → Redirect URLs:

- `https://rastasperiq.co.za/auth/callback/`
- `https://rastasperiq.co.za/auth/callback/?recovery=1`

Keep existing mobile redirects and set the Site URL to `https://rastasperiq.co.za`. Configure a production SMTP provider to send reset emails to customers outside your Supabase project team; the default Supabase email service limits recipients. Development can use equivalent callback URLs on `http://localhost:3000`.

Order status updates run in the background every eight seconds while the page is visible. Slow or failed updates retain the order content instead of replacing it with a loading placeholder.

Source-level tests passing does not make live checkout operational. See `../IMPLEMENTATION_REPORT_20261020.md` and `../MANUAL_SETUP_AND_LAUNCH_CHECKLIST.md` for verification boundaries and rollout order. Do not reapply the entire schema file to production.
